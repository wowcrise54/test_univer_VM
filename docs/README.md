# Документация MP VM Client

Главное меню документации. Каталог `docs/` содержит актуальную документацию проекта, разделённую по аудиториям и задачам.

## Пользователи (веб-интерфейс)

- [Руководство пользователя](user-guide.md) — пошаговые сценарии работы в интерфейсе: вход, роли, разделы, сканирование, уязвимости, устранение, карточки, отчёты и частые вопросы.
- [Создание задач из пресетов](team-tasks.md) — раздел «Сканирование»: инженеры создают и запускают задачи по пресетам, вводят цели (IP, подсети CIDR, диапазоны, FQDN), следят за ходом выполнения, состояниями и историей запусков.
- [Пресеты задач](task-presets.md) — роли и права, что фиксирует пресет, каталог шаблонов по рекомендациям MP VM, подготовка узлов, API и ограничения.

## Операторы и администраторы

- [Руководство оператора](operator-guide.md) — маршруты и права, сканирование и управляемый конвейер, группы и карточки активов, уязвимости, устранение, автоматизация, центр операций, сбор логов.

## Разработка

- [Архитектура системы](system-architecture.md) — фактически реализованная архитектура: компоненты, API, хранилище, интеграция с MP VM, фоновые задачи и ключевые потоки данных.
- [Границы приложения](ARCHITECTURE.md) — компактная схема основных слоёв и правила развития.
- [Разработка и развёртывание](development.md) — требования, локальный запуск, Docker Compose, конфигурация, миграции, тесты, сборка и диагностика.
- [Тестирование в Docker](testing.md) — все тесты, покрытие, lint, type-check и сборка в Docker; отдельная PostgreSQL 16 на tmpfs.
- [Тестовые demo-данные](testing-demo-data.md) — тестовый профиль, отдельный Compose-проект и временная база.
- [MCP-сервер (только чтение)](mcp.md) — read-only доступ AI-клиентов к данным приложения на порту `/mcp`: подключение, инструменты, ограничения.

## План и отчёты

- [План развития до MVP](mvp-roadmap.md) — приоритеты, новые функции, надёжность, критерии приёмки, Definition of Done.
- [Исправления корректности — 2026-10-01](P1_CORRECTNESS.md) — свидетели эксплуатации и внесённые исправления.
- [Первый этап: тесты и безопасность backend](backend-test-security-review-2026-09-24.md) — исходное состояние и итоги первого этапа.

## Правило актуальности

Документация описывает только поведение, подтверждённое текущим кодом и конфигурацией. При изменении API, маршрутов, фоновых процессов, переменных окружения или команд запуска соответствующий документ следует обновлять в той же задаче.
