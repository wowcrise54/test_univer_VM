# Пресеты задач для инженеров

Пресет — это набор параметров задачи сканирования, который настраивает администратор. Инженер Windows или Linux выбирает пресет и группы активов MP VM, после чего создаёт и запускает задачу. Профиль, учётную запись, транспорт, scope, агентов и расписание инженер не видит и не меняет.

## Роли и права

| Разрешение | Что даёт |
|---|---|
| `tasks.team` | Раздел «Сканирование»: задачи своей команды, создание по пресету, запуск, остановка, удаление, история запусков |
| `task_presets.read` | Список доступных пресетов |
| `task_presets.manage` | Раздел «Пресеты задач»: создание, изменение и архивирование пресетов; просмотр задач всех команд |

Системные роли:

- **Инженер Windows** (`engineer_windows`) и **Инженер Linux** (`engineer_linux`): `tasks.team`, `task_presets.read`, `system.read`, `operations.read`, `notifications.*`, `diagnostics.write`. Доступа к `/api/scanner-tasks/*`, справочникам MP VM (`/api/mpvm/lookups`) и подключению у них нет.
- **Оператор**: дополнительно получает `tasks.team` и может запускать задачи по пресетам.
- **Администратор**: все права.

**Команда** — это роль. Пресет доступен ролям, отмеченным в нём. Задачи команды — это задачи, созданные по пресетам, к которым у пользователя есть доступ через его роли. Изоляцию проверяет backend на каждый запрос. Чужая задача возвращает 404.

LDAP-пользователи получают роль по умолчанию из `MPVM_LDAP_DEFAULT_ROLE`. Сопоставления LDAP-групп с ролями нет. Если все LDAP-пользователи — инженеры одной ОС, укажите `engineer_windows` или `engineer_linux`. В остальных случаях роль назначает администратор в разделе «Пользователи».

## Что фиксирует пресет

- ОС (`windows` → транспорт WMI/RPC, `linux` → SSH + sudo), scope, профиль сканирования, учётная запись;
- агенты, HostDiscovery, приоритет FQDN, часовой пояс;
- расписание: по умолчанию разовый запуск;
- precheck перед сканированием и его профиль. Precheck — это «Проверка подключения» MP VM, она работает только для задач аудита;
- **разрешённые группы активов MP VM**. Инженер выбирает цели только из них, свободный ввод IP/FQDN отключён;
- максимум групп в одной задаче и одновременных запусков по пресету;
- префикс имени задачи.

Секреты в пресете не хранятся: в нём записаны только ID объектов MP VM. При сохранении backend проверяет по MP VM, что scope, профили, учётная запись и группы существуют, и обновляет имена групп.

При каждом запуске задача пересобирается из **текущей** версии пресета. Если сменить в пресете учётную запись или профиль, изменение подхватят и ранее созданные задачи. По пресету в архиве задачи не создаются и не запускаются.

Если precheck включён, задача сужается до хостов из выбранных групп, которые ответили на проверку подключения. Выбор инженера хранится отдельно, поэтому следующий запуск снова охватывает группы целиком.

## Шаблоны по рекомендациям MP VM

ID объектов MP VM у каждого стенда свои, поэтому пресеты не создаются миграцией. Завести их можно двумя способами:

- **По шаблону.** В разделе «Пресеты задач», под таблицей, есть блок «Шаблоны по рекомендациям MP VM». Кнопка **«Создать пресет»** заполняет форму. Стандартный профиль MP VM находится по имени. Если область (scope) одна, она подставляется сама, как и системная роль команды. Precheck, лимиты и префикс берутся из шаблона. Останется выбрать учётную запись и разрешённые группы активов. Если профиль или роль не нашлись, форма покажет предупреждение.
- **Из задачи.** Откройте «Задачи», выберите отлаженную задачу и нажмите **«Сделать пресетом»**. Форма заполнится параметрами задачи; отметьте роли, группы и лимиты.

Каталог составлен по справке MaxPatrol VM 28.0: «Рекомендации по использованию профилей», «Создание задач на аудит», «Определение ОС модулем Pentest», «Модуль Audit», «Модуль Pentest», «Создание регулярных задач». Он хранится в `app/services/preset_templates.py`.

Общее для всех шаблонов: разовый запуск, HostDiscovery выключен, приоритет FQDN включён.

### Почему так

- **Precheck только для аудита.** Precheck запускает в MP VM «Проверку подключения», а она доступна только для задач аудита. Поэтому в шаблонах с профилями Pentest precheck выключен.
- **HostDiscovery выключен.** В задачах аудита недоступные хосты отсекает precheck, а профили Pentest сами находят активные узлы. Для Kerberos с доменной учётной записью предварительное обнаружение работает только с профилем HostDiscovery, где включено «Присваивать активам значения FQDN из целей сбора данных».
- **Лимиты** — стартовые значения приложения, а не требование MP VM. По умолчанию MP VM выполняет одновременно до 20 подзадач Audit и до 20 подзадач Pentest, а один MP 10 Collector проводит аудит не более чем на 1000 узлах сразу. Тяжёлые профили получают меньше групп и запусков, аудит AD идёт строго по одному.
- **Префиксы** следуют схеме именования PT: `[Тип][Инфраструктура] Назначение Целевая группа`.
- **Разовый запуск.** PT советует включать расписание и запрещённое время, когда группы и фильтры уже отлажены. Расписание можно перенести в пресет из задачи через «Сделать пресетом». Запуски по расписанию MP VM выполняет сам, поэтому лимит одновременных запусков приложения их не ограничивает.

### Что не стоит давать инженерам

| Профиль | Почему |
|---|---|
| Full PenTest | С 28.0 сканирует все 65535 портов TCP и все UDP-порты, задача может идти очень долго |
| Unsafe PenTest | DoS-проверки могут сделать службы и узлы недоступными |
| Bruteforce PenTest | Подбор паролей может заблокировать учётные записи |
| HostDiscovery | Ищет новые узлы по подсетям, а пресет ограничивает цели известными группами активов |

### Подготовка узлов

- **Windows:** между узлом и MP 10 Collector открыты TCP 135, 139, 445, динамические TCP 49152–65535 и UDP 135, 137, 138, 445. Учётная запись — доменная из группы локальных администраторов, общие ресурсы Admin$, C$ и IPC$ активны. Для узлов в рабочей группе нужна локальная учётная запись и настройка UAC. Адаптивный контроль аномалий Kaspersky Endpoint Security блокирует WMI: добавьте учётную запись в исключения правила «Запуск Windows PowerShell с помощью WMI».
- **Active Directory:** чтобы увидеть результаты Windows DC Audit и Microsoft Active Directory Audit, создайте динамическую группу активов с условием `ActiveDirectory`. Для высоконагруженного каталога PT рекомендует коллектор на Linux: ему нужен FQDN цели, а NTLM для LDAP он не поддерживает.
- **Linux:** открыт TCP 22, SSH-ключи только в формате OpenSSH. В Astra Linux SE настройте уровень целостности учётной записи, в «Альт» — политику control для sudo. Узлы с ядром Linux 2.6.38 и ниже или с dmidecode 2.8 и ниже Unix SSH Audit не добавит.

## API

| Маршрут | Право |
|---|---|
| `GET /api/task-presets`, `GET /api/task-presets/{id}` | `task_presets.read` |
| `POST /api/task-presets`, `PUT /api/task-presets/{id}` (`expected_version`), `POST /api/task-presets/{id}/archive` | `task_presets.manage` |
| `POST /api/task-presets/from-task/{task_id}`: черновик из задачи | `task_presets.manage` |
| `GET /api/task-presets/templates`: каталог шаблонов; `POST /api/task-presets/from-template/{template_id}`: черновик по шаблону и предупреждения | `task_presets.manage` |
| `GET /api/task-presets/lookups`, `GET /api/task-presets/asset-groups` | `task_presets.manage` |
| `GET/POST /api/team-tasks`, `PUT /api/team-tasks/{id}` | `tasks.team` |
| `POST /api/team-tasks/{id}/start`, `/stop`, `/delete`; `GET …/runs`, `GET …/runs/{run_id}/jobs` | `tasks.team` |

`POST /api/team-tasks` принимает только `preset_id`, `asset_group_ids`, `name`, `description` и `start_now`. Любые другие поля, например `credential_id` или `targets`, отклоняются с кодом 422. Заголовок `X-Idempotency-Key` защищает от создания дубликатов при повторе запроса. Создание записывается в реестр операций с типом `team_task_create`.

Если задача создана в MP VM, но не сохранилась локально, она **не удаляется** из MP VM. Операция получает статус `needs_attention`, а `mp_task_id` записывается в ошибку для ручной сверки.

Создание, изменение, запуск, остановка и удаление задач команды, а также изменения пресетов пишутся в журнал аудита.

## Ограничения

- Лимит одновременных запусков считает активную постобработку в PostgreSQL и запуски в процессе приложения. Он рассчитан на один процесс uvicorn, а именно так приложение запускается в `Dockerfile`.
- Перед боевым использованием проверьте на стенде, что MP VM принимает задачу, где цели заданы только через `include.assetsGroups`, а `targets` пуст, и что `validation` её пропускает.
