# Пресеты задач для инженеров

Пресет — это набор параметров задачи сканирования, который настраивает администратор. Инженер Windows или Linux выбирает пресет и группы активов MP VM, после чего создаёт и запускает задачу. Профиль, учётную запись, транспорт, scope, агентов и расписание инженер не видит и не меняет.

## Роли и права

| Разрешение | Что даёт |
|---|---|
| `tasks.team` | Раздел «Сканирование»: задачи своей команды, создание по пресету, запуск, остановка, удаление, история запусков |
| `task_presets.read` | Список доступных пресетов |
| `task_presets.manage` | Раздел «Пресеты задач»: создание, изменение и архивирование пресетов; просмотр задач всех команд |

Системные роли:

- **Инженер Windows** (`engineer_windows`) и **Инженер Linux** (`engineer_linux`): `tasks.team`, `task_presets.read`, `system.read`, `operations.read`, `notifications.*`, `diagnostics.write`. Доступа к `/api/scanner-tasks/*`, справочникам MP VM (`/api/mpvm/lookups`) и подключению у них нет.
- **Оператор**: дополнительно получает `tasks.team` и может запускать задачи по пресетам.
- **Администратор**: все права.

**Команда** — это роль. Пресет доступен ролям, отмеченным в нём. Задачи команды — это задачи, созданные по пресетам, к которым у пользователя есть доступ через его роли. Изоляцию проверяет backend на каждый запрос. Чужая задача возвращает 404.

LDAP-пользователи получают роль по умолчанию из `MPVM_LDAP_DEFAULT_ROLE`. Сопоставления LDAP-групп с ролями нет. Если все LDAP-пользователи — инженеры одной ОС, укажите `engineer_windows` или `engineer_linux`. В остальных случаях роль назначает администратор в разделе «Пользователи».

## Что фиксирует пресет

- ОС (`windows` → транспорт WMI/RPC, `linux` → SSH + sudo), scope, профиль сканирования, учётная запись;
- агенты, HostDiscovery, приоритет FQDN, часовой пояс;
- расписание: по умолчанию разовый запуск;
- precheck перед сканированием и его профиль;
- **разрешённые группы активов MP VM**. Инженер выбирает цели только из них, свободный ввод IP/FQDN отключён;
- максимум групп в одной задаче и одновременных запусков по пресету;
- префикс имени задачи.

Секреты в пресете не хранятся: в нём записаны только ID объектов MP VM. При сохранении backend проверяет по MP VM, что scope, профили, учётная запись и группы существуют, и обновляет имена групп.

При каждом запуске задача пересобирается из **текущей** версии пресета. Если сменить в пресете учётную запись или профиль, изменение подхватят и ранее созданные задачи. По пресету в архиве задачи не создаются и не запускаются.

Если precheck включён, задача сужается до хостов из выбранных групп, которые ответили на проверку подключения. Выбор инженера хранится отдельно, поэтому следующий запуск снова охватывает группы целиком.

## Рекомендуемый стартовый набор

ID объектов MP VM у каждого стенда свои, поэтому пресеты не создаются миграцией. Быстрее всего завести их из уже настроенных задач:

1. Откройте «Задачи», выберите отлаженную задачу и нажмите **«Сделать пресетом»**.
2. Форма заполнится параметрами задачи. Отметьте роли, разрешённые группы и лимиты, затем сохраните.

Рекомендуемые пресеты:

| Пресет | ОС | Профиль | Учётная запись | Роль |
|---|---|---|---|---|
| Windows. Аудит (WMI/RPC) | windows | аудит | доменная учётка аудита | Инженер Windows |
| Windows. Инвентаризация без учётки | windows | Discovery/Pentest | — | Инженер Windows |
| Linux. Аудит (SSH + sudo) | linux | аудит | SSH-учётка | Инженер Linux |
| Linux. Инвентаризация без учётки | linux | Discovery/Pentest | — | Инженер Linux |

Общие настройки для всех четырёх: разовый запуск, precheck включён, не больше 5 групп в задаче, не больше 3 одновременных запусков.

## API

| Маршрут | Право |
|---|---|
| `GET /api/task-presets`, `GET /api/task-presets/{id}` | `task_presets.read` |
| `POST /api/task-presets`, `PUT /api/task-presets/{id}` (`expected_version`), `POST /api/task-presets/{id}/archive` | `task_presets.manage` |
| `POST /api/task-presets/from-task/{task_id}`: черновик из задачи | `task_presets.manage` |
| `GET /api/task-presets/lookups`, `GET /api/task-presets/asset-groups` | `task_presets.manage` |
| `GET/POST /api/team-tasks`, `PUT /api/team-tasks/{id}` | `tasks.team` |
| `POST /api/team-tasks/{id}/start`, `/stop`, `/delete`; `GET …/runs`, `GET …/runs/{run_id}/jobs` | `tasks.team` |

`POST /api/team-tasks` принимает только `preset_id`, `asset_group_ids`, `name`, `description` и `start_now`. Любые другие поля, например `credential_id` или `targets`, отклоняются с кодом 422. Заголовок `X-Idempotency-Key` защищает от создания дубликатов при повторе запроса. Создание записывается в реестр операций с типом `team_task_create`.

Если задача создана в MP VM, но не сохранилась локально, она **не удаляется** из MP VM. Операция получает статус `needs_attention`, а `mp_task_id` записывается в ошибку для ручной сверки.

Создание, изменение, запуск, остановка и удаление задач команды, а также изменения пресетов пишутся в журнал аудита.

## Ограничения

- Лимит одновременных запусков считает активную постобработку в PostgreSQL и запуски в процессе приложения. Он рассчитан на один процесс uvicorn, а именно так приложение запускается в `Dockerfile`.
- Перед боевым использованием проверьте на стенде, что MP VM принимает задачу, где цели заданы только через `include.assetsGroups`, а `targets` пуст, и что `validation` её пропускает.
