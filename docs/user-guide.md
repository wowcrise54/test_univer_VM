## 1. Что такое MP VM Client

MP VM Client — веб-приложение-надстройка над MaxPatrol VM (MP VM). Оно помогает:

- создавать и запускать задачи сканирования и следить за ними;
- автоматически сохранять результаты в **локальную базу** — карточки активов, найденные уязвимости, паспорта уязвимостей;
- анализировать уязвимости по всей инфраструктуре: дашборды, тренды, выгрузки;
- вести **устранение**: назначать ответственных, сроки (SLA), проверять исправление повторным сканированием;
- настраивать расписания запусков и получать уведомления.

Важно понимать, откуда берутся данные. Разделы «Уязвимости», «Карточки активов», «Паспорта», «Дашборды» и «Выборки активов» показывают **локальную копию** данных, а не живое состояние MP VM. Чтобы данные появились или обновились, нужно выполнить сканирование, загрузку карточки или PDQL-запрос. Удаление локальной карточки или паспорта **не меняет** MP VM.

## 2. Вход и роли

### Как войти

Откройте адрес приложения в браузере (по умолчанию `http://127.0.0.1:8000`, в вашей организации адрес может быть другим). На экране «Вход в приложение» выберите способ входа:

- **Локально** — логин и пароль, созданные администратором приложения;
- **LDAP** — доменная учётная запись (доступно, если администратор включил LDAP).

Сессия хранится в защищённой cookie и закрывается при выходе, блокировке пользователя или смене пароля.

Если вместо формы входа вы видите предупреждение «Первый администратор ещё не создан» — приложение не настроено, обратитесь к администратору.

### Роли

Что вы видите в меню, зависит от роли. Недоступные разделы и кнопки скрыты, а сервер дополнительно проверяет права при каждом действии.

| Роль | Что может |
| --- | --- |
| **Администратор** (`admin`) | Всё, включая пользователей, роли, подключение к MP VM, пресеты задач, журнал аудита. |
| **Оператор** (`operator`) | Просмотр всех данных, управление задачами, операциями, карточками активов и устранением; запуск задач по пресетам. Без доступа к пользователям и безопасности. |
| **Наблюдатель** (`viewer`) | Только чтение и формирование доступных отчётов. |
| **Инженер Windows / Linux** | Только раздел «Сканирование»: создание и запуск задач по готовым пресетам своей команды. |

Администратор может клонировать системные роли, собирать собственные и назначать пользователю несколько ролей — права объединяются.

## 3. Устройство интерфейса

**Меню слева** разделено на группы:

| Группа | Разделы |
| --- | --- |
| Основное | Обзор, Сканирование, Отчётность, Дашборды, Уязвимости, Устранение |
| Инструменты | Подключение, Задачи, Группы активов, Операции, Карточки активов, Автоматизация, Выборки активов, Паспорта |
| Администрирование | Пресеты задач, Пользователи |

**Шапка** показывает статус подключения к MP VM. У администратора он ведёт в раздел «Подключение». Над страницей может появиться системная полоса — она видна только при проблемах (например, недоступна база данных или устарели данные операций).

**Типовые элементы:**

- таблицы умеют фильтроваться, сортироваться и листаться по страницам;
- при ошибке загрузки показывается сообщение и кнопка **Повторить**;
- опасные действия (удаление, массовый пересчёт, архивирование) требуют подтверждения в отдельном окне;
- черновик формы задачи сохраняется в браузере и не пропадает при обновлении страницы.

Если у вас не открывается раздел из этого руководства — у вашей роли нет нужного права. Обратитесь к администратору.

## 4. Сценарии работы

### 4.1. Первичная настройка (администратор)

1. Откройте **Подключение** и введите параметры доступа к MP VM (логин/пароль или готовый токен — как принято в вашей организации).
2. Убедитесь, что статус в шапке показывает успешное подключение.
3. Загрузите справочники MP VM: учётные записи, области сканирования (scopes), профили сканирования. Без них задачи создать нельзя.
4. Создайте пользователей и назначьте роли в разделе **Пользователи**.

> Для плановых запусков по расписанию приложению нужны серверные учётные данные MP VM, заданные при развёртывании. Подключение, выполненное только через браузер, после перезапуска приложения планировщиком не используется.

### 4.2. Запустить сканирование как оператор

1. Откройте **Задачи** и нажмите создание новой задачи (или выберите существующую).
2. Заполните форму: область (scope), профиль сканирования и хотя бы одну цель. При необходимости укажите учётные данные, транспорт (Windows — WMI/RPC, Linux/Unix — SSH + sudo), коллекторы, исключения и HostDiscovery.
3. Нажмите **Проверить** — приложение сверит задачу с MP VM.
4. Нажмите **Запустить**. Кнопка неактивна, пока не готовы база, сессия MP VM, справочники, scope, профиль и цели.
5. Щёлкните по строке задачи — откроется окно **Результаты задачи** с подзадачами, статусами, временем и ошибками.
6. После сканирования приложение само импортирует результаты и пересобирает карточки активов. Ход можно смотреть под таблицей задач или в разделе **Операции**.

**Дополнительные параметры запуска:**

- **Precheck** — проверка подключения к целям перед сканированием. В основное сканирование идут только успешные цели.
- **Строгий режим** — не запускает задачу, пока по ней идут другие процессы, и считает предупреждения и ошибки заданий сбоем.
- **Таймаут** — по истечении времени в MP VM отправляется запрос на остановку.

Кнопки **Остановить** и **Удалить** есть в строке задачи. При удалении нужно ввести идентификатор задачи; локальная запись исчезнет только после подтверждения от MP VM.

### 4.3. Запустить сканирование как инженер (по пресету)

Если у вас роль «Инженер Windows» или «Инженер Linux», вам доступен только раздел **Сканирование**.

1. Нажмите создание задачи и выберите **пресет** — готовый набор параметров, настроенный администратором (профиль, учётная запись, транспорт и т. д. вам не показываются).
2. Выберите **группы активов**, которые нужно просканировать. Список групп ограничен пресетом; вводить IP или FQDN вручную нельзя.
3. Укажите название и описание при необходимости, затем создайте и запустите задачу.
4. В таблице видны ваши задачи и задачи команды, их состояние и история запусков. Задачи можно остановить и удалить.

Если у пресета включён precheck, сканируются только те хосты выбранных групп, которые ответили на проверку подключения. При следующем запуске снова проверяются группы целиком. Лимиты числа групп в задаче и одновременных запусков задаёт пресет — при превышении система сообщит об этом.

### 4.4. Управляемый цикл на странице «Обзор»

«Обзор» (`/vm`) — стартовая страница. Она ведёт полный цикл «сканирование → загрузка → карточки → сверка находок» одним процессом.

1. Выберите задачу MP VM.
2. При необходимости включите проверку доступности целей, запрет запуска при активных процессах и задайте таймаут (1–1440 минут).
3. Нажмите **Проверить перед запуском**. Сервер сообщит о блокировках (задача удалена, нет права, MP VM недоступен) и предупреждениях.
4. Если есть только предупреждения, установите флажок **Я понимаю предупреждения и подтверждаю запуск** и запустите процесс.
5. В карточке процесса видны этапы, прогресс и сообщения. Для подходящих состояний доступны **Остановить** и **Повторить**. При повторе сбоя на этапе сверки сканирование заново не запускается — используются уже сохранённые результаты.

Статусы процесса: *В очереди*, *Выполняется*, *Отменяется*, *Завершён*, *Завершён с ошибками*, *Ошибка*, *Отменён*.

### 4.5. Найти и проанализировать уязвимости

1. Откройте **Уязвимости** (или **Дашборды** для обзора).
2. Вкладки раздела:
   - **Обзор риска** — сводка, распределение по критичности, самые распространённые уязвимости, хосты с наибольшим числом находок, тренды и история риска за 90 дней;
   - **Контроль и отчёты** — критические уязвимости в двух контурах (внешний контур 10.255.0.0/16 и организация), а также список активов со сканом старше 30 дней или без даты скана;
   - **Статистика устранений** — подтверждённые исправления за 7/30/90 дней (нужно право просмотра устранения).
3. Отфильтруйте список по тексту (CVE, название), хосту, критичности и источнику (карточка актива, ОС, установленное ПО, Docker).
4. Выберите уязвимость — откроется список затронутых хостов. Из строки хоста можно открыть конкретную находку и паспорт уязвимости.

### 4.6. Взять находку в устранение

1. В списке хостов выбранной уязвимости откройте находку и нажмите кнопку взятия в устранение (нужны права на просмотр данных, просмотр и управление устранением).
2. Перейдите в **Устранение** — там появился кейс по паре «актив + уязвимость».
3. Назначьте ответственного, срок, статус и добавьте комментарий.
4. Для нескольких кейсов отметьте их галочками и используйте массовые действия.
5. Если риск принимается или находка — ложное срабатывание, оформите **исключение**: обязательны обоснование и будущая дата окончания. По истечении срока кейс вернётся в открытую очередь автоматически.

**Как закрывается кейс.** Статус «устранено» ставится не вручную, а автоматически: после свежего полного сканирования, в котором находка больше не обнаружена. Если уязвимость появится снова, кейс откроется заново.

**Сроки (SLA).** По умолчанию: Critical — 7 дней, High — 30, Medium — 90, Low — 180. Матрицу можно изменить на странице «Устранение». Кнопка **Сохранить и пересчитать открытые** меняет сроки всех открытых кейсов, поэтому просит подтверждения. Вручную заданный срок политикой не перезаписывается.

**Кампании.** Кампания объединяет кейсы и запускает проверочное сканирование их активов. Результат открывается как процесс на странице «Обзор» и автоматически обновляет состояние кейсов.

### 4.7. Работа с карточками активов

Карточка — подробный локальный снимок актива: ОС, ПО, уязвимости, сетевые параметры и прочее.

1. В **Карточки активов** выполните PDQL-поиск кандидатов. Запрос можно ограничить группой, ID актива, числом активов и размером пачки.
2. Выберите актив и соберите карточку:
   - **с сохранением в БД** — фоновая задача с прогрессом и возможностью остановки;
   - **без сохранения** — карточка сразу открывается для просмотра.
3. Сохранённые карточки можно искать, сортировать, открывать, пересканировать по IP и удалять (только локально).
4. Из карточки можно перейти к локальному паспорту уязвимости. Если его нет, система просто сообщит об этом.
5. Массовое обновление всех или только устаревших карточек выполняется как фоновая операция — следите за ней в **Операциях**.

Ограничения сборки: не более 50 000 активов в поиске, размер пачки до 10 000, до 5 000 элементов в коллекции, глубина дерева до 8.

### 4.8. Выборки по карточкам

Раздел **Выборки активов** отвечает на вопросы вида «на каких хостах открыт порт X и установлено ПО Y». Он работает только с локальными карточками и не обращается к MP VM.

1. Постройте дерево условий (И/ИЛИ, до 20 правил, до трёх уровней групп).
2. Выберите область совпадения: *хост* (условия могут относиться к разным частям хоста) или *та же сущность* (все условия должны выполняться для одного и того же элемента, например одного правила firewall).
3. Настройте сортировку и колонки, сохраните представление.
4. Выгрузите результат в CSV — выгружается вся выборка, а не только текущая страница.

Над конструктором показано покрытие индекса: после обновления приложения старые карточки индексируются в фоне.

### 4.9. Динамические группы активов

1. В **Группы активов** задайте имя, описание и условия (поиск, точное совпадение, начало строки, исключение, список; для IP — принадлежность подсети).
2. Нажмите **Предпросмотр**, чтобы увидеть состав, затем сохраните.
3. Состояния: *актуальна*, *требует пересчёта*, *пересчитывается*, *ошибка*.
4. Для актуальной группы доступны **Сканировать группу** (сканирование и обновление карточек) и **Проверить устранение** (то же плюс сверка находок). Нужно право запуска задач.
5. Состав можно пересчитать, вручную добавить актив по `asset_id` или исключить участника. Группы можно архивировать, в том числе сразу несколько.

Из выбранной уязвимости также можно создать группу всех затронутых активов.

### 4.10. Паспорта уязвимостей

Паспорт — справочная карточка уязвимости: описание, критичность, CVSS, CVE, способ устранения, ссылки.

1. В **Паспорта** выполните PDQL-запрос; список сохранится локально. Можно ограничить запрос и включить фоновую загрузку подробностей — в панели видны прогресс, ошибки и кнопка остановки.
2. Ищите по CVE, названию, `internalId` или пакету; сортируйте и листайте (по 50 записей).
3. Откройте паспорт — подробности подгрузятся, если их ещё нет. Кнопка **Обновить** заново запрашивает данные из MP VM.
4. Удаление убирает паспорт только из локальной базы; позже его можно загрузить снова.

### 4.11. Отчёты и выгрузки

Раздел **Отчётность**:

- скачивание отчётов по уязвимостям: общий XLSX и детальные CSV по ОС, ПО и Docker-контейнерам (без выбора активов в отчёт попадают все сохранённые хосты);
- при наличии права управления выгрузками — **PDQL-выгрузка**: выполняет запрос, сохраняет результат в локальную базу и CSV.

В PDQL-выгрузке есть опция удаления активов из MP VM. По умолчанию она **выключена**; при включении кнопка называется «Экспортировать и удалить из MP VM», а активы удаляются только после успешного локального сохранения. Используйте её осознанно: удаление в MP VM необратимо.

### 4.12. Расписания и уведомления

Раздел **Автоматизация** состоит из трёх вкладок.

1. **Расписания.** Выберите задачу MP VM, название, периодичность (ежедневно, по будням, по понедельникам, 1-го числа месяца) и время. Для особого графика выберите **Свой cron** (формат «минута час день-месяца месяц день-недели»). Часовой пояс указывается отдельно. Пропущенные запуски не догоняются. Расписание можно поставить на паузу или удалить (с подтверждением).
2. **Запуски.** История и состояние запусков; активный запуск можно отменить.
3. **Уведомления.** События системы, которые можно отмечать прочитанными. Ежедневный дайджест просроченных и приближающихся сроков устранения приходит сюда, а при настройке администратором — и во внешний webhook.

### 4.13. Администрирование

**Пользователи** (по правам): список пользователей, назначение ролей, клонирование и создание ролей, просмотр журнала аудита (хранится 365 дней).

**Пресеты задач** (администратор): создайте пресет вручную, по готовому шаблону из каталога рекомендаций MP VM («Создать пресет») или из отлаженной задачи (кнопка **Сделать пресетом** в разделе «Задачи»). Выберите учётную запись, разрешённые группы активов, роли-получатели и лимиты. В пресете хранятся только идентификаторы объектов MP VM, но не пароли. Подробности и таблица шаблонов — в [task-presets.md](task-presets.md).

## 6. Фоновые операции и ошибки

Долгие действия (постобработка сканирования, сборка и обновление карточек, загрузка паспортов, PDQL-выгрузки, запуски автоматизации) выполняются в фоне. Они не зависят от открытой вкладки — можно закрыть браузер и вернуться позже. После перезапуска приложения операции восстанавливаются или помечаются как прерванные и их можно повторить.

**Центр операций** (`/operations`):

- фильтры по тексту, состоянию и типу, сортировка, сохранённые представления, по 50 записей на странице;
- активные состояния: *В очереди*, *Выполняется*, *Останавливается*, *Восстанавливается*; конечные: *Завершено*, *С ошибками*, *Ошибка*, *Отменено*, *Прервано*;
- в деталях операции видны этап, прогресс, `Trace ID`, хронология, параметры, результат и ошибка;
- кнопки **Остановить** и **Повторить** появляются, только если сервер разрешает действие. Повтор защищён от дублей;
- есть ссылка на диагностический архив — приложите его к обращению в поддержку.

**Что важно помнить:**

- остановка — это *запрос* на остановку; уже начатая работа в MP VM может завершиться не сразу;
- если MP VM, база данных или сессия недоступны, приложение не скрывает это: запуск блокируется или показывается сообщение об ошибке;
- сообщения об ошибках содержат понятный текст для оператора и `Trace ID`. Название ошибки и `Trace ID` помогут администратору быстро найти причину.

## 7. Частые вопросы

**Кнопка «Запустить» неактивна.** Проверьте, что в шапке MP VM подключён, справочники загружены, выбраны scope, профиль и хотя бы одна цель. Кнопка также блокируется при недоступной базе данных.

**Я не вижу нужный раздел или кнопку.** У вашей роли нет соответствующего права. Попросите администратора проверить роль в разделе «Пользователи».

**В разделе «Уязвимости» пусто.** Данные локальные. Выполните сканирование, соберите карточки или загрузите данные PDQL-запросом.

**Показано «Данные неполные — значения занижены».** При подсчёте часть данных была усечена, и числа — нижняя оценка. Обновите карточки и повторите.

**Цифры «уязвимостей», «находок» и «хостов» различаются.** Уязвимость — уникальный тип проблемы; находка — её обнаружение на конкретном хосте и объекте; затронутый хост — уникальный актив хотя бы с одной находкой. Одна уязвимость встречается на многих хостах, а на одном хосте у неё может быть несколько находок.

**Кейс устранения не закрылся.** Он закрывается только после свежего *полного* сканирования, где находка не обнаружена. Запустите проверку устранения для актива, группы или кампании.

**Что будет, если удалить карточку или паспорт?** Удалится только локальная запись; MP VM не меняется. Данные можно загрузить заново.

**Можно ли удалить задачу случайно?** Нет: нужно ввести идентификатор задачи и подтвердить. Локальная строка исчезает после подтверждения удаления в MP VM.

**Приложение пишет, что сессия MP VM не установлена.** Администратору нужно заново подключиться в разделе «Подключение».

**Куда обращаться при сбое.** Откройте проблемную операцию в «Операциях», скопируйте `Trace ID` и скачайте диагностический архив, затем передайте их администратору.

## 8. Глоссарий

| Термин | Значение |
| --- | --- |
| **MP VM** | MaxPatrol VM — система управления уязвимостями, источник данных для приложения. |
| **Актив** | Хост или устройство в инфраструктуре. |
| **Карточка актива** | Локальный подробный снимок актива. |
| **Находка (finding)** | Конкретное обнаружение уязвимости на хосте. |
| **Паспорт уязвимости** | Справочная информация об уязвимости: описание, CVSS, CVE, способ устранения. |
| **Задача сканирования** | Набор целей, профиля и учётных данных для запуска сканирования в MP VM. |
| **Scope** | Область сканирования в MP VM. |
| **Профиль сканирования** | Набор проверок, выполняемых на целях. |
| **Precheck** | Предварительная проверка подключения к целям. |
| **Пресет** | Готовый шаблон задачи, настроенный администратором. |
| **Постобработка** | Автоматический импорт результатов и сборка карточек после сканирования. |
| **Кейс устранения** | Рабочая запись по паре «актив + уязвимость». |
| **SLA** | Срок, в который уязвимость нужно устранить, по критичности. |
| **Кампания** | Группа кейсов с общим проверочным сканированием. |
| **PDQL** | Язык запросов к данным MP VM. |
| **Динамическая группа** | Группа активов, состав которой вычисляется по условиям. |
| **Trace ID** | Идентификатор для поиска событий в журналах при диагностике. |
